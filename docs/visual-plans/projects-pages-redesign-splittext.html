Redesign /projects pages with plain language and SplitText headers

Better layout on /projects and /projects/[id], plain-English case studies (tech names kept), animated SplitText headers.

Context

Task T-04 asks for a better layout, design, and UI/UX on every /projects/* page. It also asks for plain English everywhere except tech-stack names, and React Bits SplitText for text headers.

Today the case-study copy is full of jargon: deterministic, role-scoped, lifecycle, persistence, server-enforced boundaries. The case-study page also has layout issues:

  • The banner is hidden inside the Overview card.
  • Tags show twice.
  • Some text is cut off by truncate.
  • Two arrow icons look like links but do nothing.

Decisions made: the shared sections (ProjectsSection, TechStackSection, ProjectCard) are redesigned too, so the home page gets the same upgrade. All case-study text in src/data/projects.ts is rewritten in full.

Steps

  1. Install SplitText. Run npx shadcn@latest add @react-bits/SplitText-JS-CSS. If the CLI does not know the registry, add "@react-bits": "https://reactbits.dev/r/{name}.json" to components.json → registries and run it again. This adds gsap and @gsap/react.
    • Read the generated file before using it.
    • Add prefers-reduced-motion support: the text shows at once, with no animation.
    • Set aria-label on the header and hide the split letters from screen readers, so they read the whole text, not single letters.
  2. Use SplitText for headers. Replace these headers with SplitText:
    • "Featured work"
    • "Design & Development Stacks"
    • the project title (h1)
    • each case-study section heading (h2)
    Each header plays once when it scrolls into view.
  3. Redesign the case-study page. Keep the structure and the parsing logic. Make these changes:
    • Move the banner into the hero.
    • Remove the duplicate tags.
    • Remove truncate so text wraps.
    • Remove the arrows that are not links.
    • Use plain section labels.
    • Add a Next project link that wraps from the last project to the first.
  4. Update the index and shared sections. Use plain intro copy. Rename the "Case study" button to "Read the story". Make small spacing fixes only.
  5. Rewrite the copy in src/data/projects.ts. Cover all 5 projects and the placeholder. Keep tech names, numbers, and facts. Keep the text format the page parses (see below).
  6. Add one check, src/data/projects.test.ts. It confirms that the rewritten copy still matches the format the page parses.

The copy rewrite must keep the text format the page parses.

  • Blocks are separated by \n\n, and the first line of a block is its title.
  • role uses - bullet lines.
  • techStack rows use the form - Name — description, with a real em dash.
  • The first block of results is made of - lines. The page hides the RemindLy line that starts with "On August 17".
  • In finalProduct, the first sentence of each block becomes its title.

The new projects.test.ts catches a section that ends up empty.
